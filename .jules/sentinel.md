## 2025-10-21 - Assignment in Conditional Error Handling
**Vulnerability:** An assignment operator (`if (bSuccess = FALSE)`) was used instead of a comparison operator (`==`) in database insert result checking in `termsrv/license/tlserver/server/license.cpp`.
**Learning:** Single `=` in `if` statements can silently reset status variables to `FALSE`/0, causing error checks to be skipped and methods to return success even when backend operations fail.
**Prevention:** Always use strict compiler warnings (`-Wparentheses` / `-Wlogical-op` / MSVC `C4706`) and explicit `FALSE == var` or `!var` syntax to prevent accidental assignment in conditionals.

## 2026-10-31 - Signed/Unsigned Mismatch in Protocol Length Bounds Checks
**Vulnerability:** In `base/fs/srv/smbraw.c`, `immediateLength > (WorkContext->ResponseBuffer->DataLength - SmbGetUshort(&request->DataOffset))` compared an unsigned length (`immediateLength` is `ULONG`) against a subtraction involving signed `CLONG` (`DataLength`). When `DataOffset` exceeded `DataLength`, negative subtraction was promoted to a huge unsigned value, bypassing the length check and passing an out-of-bounds pointer into `FastIoWrite`.
**Learning:** Bounds checks that subtract user-controlled offsets before validating that `offset <= total_length` risk underflow; mixing signed buffer lengths with unsigned offsets promotes negative differences to large positive integers, inverting the validation condition.
**Prevention:** Always explicitly check `offset <= length` before subtracting, and ensure all operands in bounds comparisons are cast or declared as matching unsigned integer types (`ULONG`) without underflow potential.

## 2026-11-02 - Unbounded Backwards Pointer Search in Path Canonicalization
**Vulnerability:** In `ds/netapi/netlib/canon.c`, `ConvertPathMacros` passed `ptr - 1` into `BackUpPath(Path, ptr - 1)` after collapsing a `..` component to the start of the buffer (`ptr == Path`). `BackUpPath` tested `Path != Stopper` only after dereferencing. Because `Path < Stopper`, the equality stop condition never matched, causing the loop to scan backwards out-of-bounds into stack memory until encountering an arbitrary `\` (CVE-2008-4250).
**Learning:** Backwards pointer scans that rely on strict pointer equality `ptr != stopper` fail catastrophically if called with `ptr < stopper`, leading to stack underflows and subsequent out-of-bounds writes if the scan result is used as a copy destination.
**Prevention:** Always ensure search routines enforce directional relational bounds (`Path > Stopper`) and validate `Path >= Stopper` prior to search loops. In callers, guard against decrementing pointers at buffer boundaries (`(ptr > Path) ? BackUpPath(Path, ptr - 1) : NULL`).

## 2026-11-03 - Uninitialized Stack Buffer in Path Canonicalization with Empty Prefix
**Vulnerability:** In `ds/netapi/netlib/canon.c`, `CanonicalizePathName` branched on `if (prefixLen)` when `ARGUMENT_PRESENT(PathPrefix)` was true. When `PathPrefix` was present but empty (`*PathPrefix == '\0'`), `prefixLen` was 0, bypassing both the prefix copy and the `else` block (`pathBuffer[0] = 0`), leaving the 521-element `pathBuffer` stack array uninitialized prior to `STRCAT(pathBuffer, PathName)`.
**Learning:** Checking string presence (`ARGUMENT_PRESENT` or `ptr != NULL`) without ensuring zero-length strings also take an initialization path leaves stack buffers uninitialized, allowing string concatenation routines (`strcat`/`wcscat`) to traverse residual stack garbage, corrupt memory, or overflow the buffer.
**Prevention:** Always ensure all branches of length-conditioned code initialize destination buffers (e.g. `pathBuffer[0] = 0` for empty inputs), and normalize empty strings (`""`) to NULL at API entry points where appropriate.

## 2026-11-08 - Overly Permissive Memory Protection on Physical Memory Views
**Vulnerability:** In `base/ntos/vdm/i386/vdminit.c`, `VdmpInitialize` mapped physical page zero into the caller's user address space using `PAGE_READWRITE` instead of `PAGE_READONLY` during VDM initialization, allowing a race window where concurrent threads could write to physical page zero / IVT / BIOS memory (CVE-2007-1206).
**Learning:** Mapping sensitive physical hardware resources (`\Device\PhysicalMemory`) into user space with write permissions violates least privilege when the kernel only intends to read or snapshot initial state. Any write window in user space exposes physical memory to modification by other threads in the process.
**Prevention:** Always enforce least privilege on memory section mappings—use `PAGE_READONLY` for read-only sources and copy physical memory buffers via kernel mode rather than exposing writable views directly to user mode.

## 2026-11-10 - NetBIOS Name Padding and Protocol Payload Length Conflation
**Vulnerability:** In `base/fs/srv/svcsupp.c`, `SrvSendSecondClassMailslot` space-padded a NetBIOS domain name in `domainName[COMPUTER_NAME_LENGTH+1]` (16 bytes) and then executed `domainName[++domainLength] = '\0'`. Because `domainLength` was 15 after padding, pre-increment wrote to index 16 (1 byte stack buffer overflow, CWE-121) while leaving index 15 uninitialized (CWE-200 stack disclosure in datagram transmission). Furthermore, `domainLength` (16) was subsequently reused for mailslot transaction payload offsets and string copying (`RtlCopyMemory(domainInData, Domain, domainLength + 1)`), reading 17 bytes from input string `Domain` regardless of its actual length (CWE-125 out-of-bounds read).
**Learning:** Conflating fixed-size protocol wire field formatting (such as 16-byte space-padded NetBIOS names) with variable-length string payload lengths creates a cascade of memory safety defects. Pre-increment indexing (`[++len]`) at the upper loop bound routinely causes off-by-one writes and leaves preceding bytes uninitialized.
**Prevention:** Keep fixed-width protocol buffer formatting strictly separate from variable-length payload string lengths (`strlen`). Always use explicit constant indexing (`buf[MAX_LEN] = '\0'`) rather than pre-incrementing loop counters, and initialize destination buffers completely before transmission.
