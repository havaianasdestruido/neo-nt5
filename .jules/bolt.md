## 2025-05-18 - Pathlib Object Overhead in Large Monorepos
**Learning:** In codebases with hundreds of thousands of tracked files (e.g., ~278k files), `pathlib.PurePosixPath` object instantiations and property traversals (`.parent`, `.parts`) create tens of millions of python function calls and object allocations, causing severe performance bottlenecks (~46s runtime). Simple string operations (`rfind('/')`, string slicing) combined with early termination when visiting known parent paths reduce execution time by over 15x.
**Action:** When indexing or traversing file paths at scale (100k+ paths), prefer raw string slicing and memoized/early-exit parent traversal over instantiating `pathlib` objects for every file.

## 2025-05-19 - Caching System Calls & Path String Normalization for High-Volume Link Validation
**Learning:** When validating tens of thousands of relative markdown links (~56k links across documentation pages), making ~56k unmemoized `Path.exists()` / `os.path.exists()` calls generates massive call overhead and ~56k redundant `stat()` system calls (~5.1s runtime). Memoizing `os.path.exists()` with `@lru_cache` while keeping standard `urllib.parse.urlsplit()` reduces runtime to ~1.4s (a ~3.6x speedup) with full URL scheme/relative-link correctness.
**Action:** For high-volume validation loops that repeatedly check file existence, use `@lru_cache` for filesystem `os.path.exists` checks rather than hand-rolling URL parsers.

## 2025-05-20 - Fast Pre-filtering and Single-Pass Directory Grouping
**Learning:** Parsing 13,000+ build definition files line-by-line with regex without pre-filtering caused over 400,000 regex evaluations. Adding a fast character check (`"=" not in line`) skipped 90% of lines before regex execution and early loop exit after finding both declarations (`len(found) == 2`) eliminated redundant line scans. Additionally, grouping 56,000+ directories by root tree in a single pass (`defaultdict(list)`) eliminated an O(roots * directories) loop (~1.18M iterations). Combined with `open()` over `Path`, runtime dropped from ~2.5s to ~1.4s (~40% speedup).
**Action:** Pre-filter strings with cheap substring checks before executing regexes on thousands of lines, terminate loops early once target data is collected, and group items into dictionaries in a single pass instead of re-scanning full sets for every key.

## 2025-05-21 - Avoiding Inner-Loop Path Object Allocations in Hot Link Checking Loops
**Learning:** In link verification loops handling ~56,000 links across Markdown files, instantiating `Path(dest_str)` on every loop iteration to look up entries in a `Path`-keyed dictionary creates tens of thousands of unnecessary Python object allocations (`PosixPath` instantiation, `parse_parts`, etc.). Keying dictionary caches by raw path strings (`str(p)`) and using string path operations (`os.path.dirname`, `os.path.basename`) inside inner loops eliminates object allocation overhead and speeds up the link verification loop by ~2.7x (reducing loop execution time from ~1.40s to ~0.51s).
**Action:** Always key dictionary lookup caches with raw path strings instead of `Path` objects when executing high-volume inner loops.

## 2026-10-31 - Fast Relative Link Target Parsing in Markdown Documentation Checkers
**Learning:** In documentation validation tools checking ~56,000 relative markdown links, invoking `urllib.parse.urlsplit()` and `urllib.parse.unquote()` for every link accounts for over 40% of the runtime (~0.63s). Since the vast majority (>99.9%) of links are relative without percent-encoding or URL schemes, replacing `urlsplit()` with fast substring checks (`find(':')`, `find('#')`) and gating `unquote()` behind `'%' in path` reduced link validation inner-loop runtime from ~0.76s to ~0.49s (~1.55x speedup). Additionally, capping `split('/', 2)` during repository file parsing avoided tens of thousands of extra string list allocations across ~278k files, speeding up overall execution from ~1.55s to ~1.07s (~1.44x speedup).
**Action:** When validating relative links or URLs in bulk where URL schemes or percent-encodings are rare, use fast substring slicing and conditional unquoting rather than invoking `urlsplit` and `unquote` on every item.
